# Migration to Dependency Injection Pattern

Этот скрипт помогает мигрировать код с глобальных инстансов сервисов на паттерн Dependency Injection через ServiceContainer.

## Использование

### 1. Предварительный просмотр изменений (dry-run)

```bash
cd /Users/elbek/panel
python backend/scripts/migrate_to_di.py --dry-run
```

Это покажет все файлы, которые будут изменены, без фактического применения изменений.

### 2. Применение изменений

```bash
python backend/scripts/migrate_to_di.py --apply
```

⚠️ **ВНИМАНИЕ**: Перед применением убедитесь, что:
- У вас есть git commit всех текущих изменений
- Вы протестировали dry-run и проверили изменения
- У вас есть возможность откатить изменения (git)

## Что делает скрипт

1. **Находит все глобальные инстансы** сервисов (например, `cache_service = CacheService()`)
2. **Находит все импорты** этих сервисов
3. **Находит все использования** этих сервисов в коде
4. **Генерирует план миграции**:
   - Удаляет глобальные инстансы (заменяет на комментарий)
   - Удаляет импорты глобальных инстансов
   - Добавляет `get_service()` вызовы перед первым использованием
   - Добавляет импорт `from ...utils.service_helpers import get_service`

## Пример изменений

### До:
```python
from ...services.cache import cache_service

def some_function():
    cache_service.get("key")
```

### После:
```python
from ...utils.service_helpers import get_service

def some_function():
    cache_service = get_service('cache_service')
    cache_service.get("key")
```

## Обратная совместимость

Некоторые сервисы могут оставить глобальные инстансы для обратной совместимости:
- `cache_service` - используется во многих местах
- `product_service` - используется во многих местах

В этом случае скрипт не будет их удалять, но заменит импорты на `get_service()`.

## Ручная проверка

После применения изменений рекомендуется:

1. Проверить, что все импорты корректны
2. Запустить линтер: `pylint backend/` или `flake8 backend/`
3. Запустить тесты (если есть)
4. Проверить, что приложение запускается

## Откат изменений

Если что-то пошло не так:

```bash
git checkout -- backend/
```

Или выборочно:

```bash
git checkout -- backend/services/cache/cache_service.py
```
