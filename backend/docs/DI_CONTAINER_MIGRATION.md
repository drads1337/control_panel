# DI Container Migration Plan

## Текущее состояние

Проект использует кастомный DI контейнер (`ServiceContainer` в `core/service_container.py`), который:
- Поддерживает три scope: SINGLETON, REQUEST, TRANSIENT
- Имеет lifecycle hooks (on_init, on_cleanup)
- Автоматически разрешает зависимости через интроспекцию конструкторов
- Интегрирован с Flask (request-scoped сервисы через `g`)

## Проблемы текущей реализации

1. **Когнитивная нагрузка**: Новым разработчикам нужно изучать кастомный API
2. **Поддержка**: Нет стандартной документации и community support
3. **Тестирование**: Сложнее мокировать и тестировать
4. **Over-engineering**: Для большинства случаев достаточно простого паттерна Proxy

## Рекомендации

### Вариант 1: Упрощение текущего контейнера (Рекомендуется)

**Плюсы:**
- Минимальные breaking changes
- Сохраняет существующую функциональность
- Можно делать постепенно

**Действия:**
1. Заморозить API контейнера (уже сделано - см. комментарии в коде)
2. Упростить lifecycle hooks - убрать если не используются критически
3. Добавить больше документации и примеров
4. Рассмотреть упрощение до двух scope: SINGLETON и REQUEST

### Вариант 2: Миграция на Dependency Injector

**Плюсы:**
- Стандартная библиотека с хорошей документацией
- Активная поддержка сообщества
- Больше возможностей для тестирования

**Минусы:**
- Требует рефакторинга всех сервисов
- Breaking changes для всего кода
- Время на миграцию: ~2-3 недели

**Действия:**
1. Установить `dependency-injector`
2. Создать новый контейнер параллельно
3. Мигрировать сервисы постепенно
4. Удалить старый контейнер после полной миграции

### Вариант 3: Использование Flask extensions pattern

**Плюсы:**
- Нативный подход для Flask
- Простота использования
- Хорошая интеграция с Flask lifecycle

**Минусы:**
- Потеря гибкости текущей реализации
- Нужно переписать всю регистрацию сервисов

## Текущий вердикт

**Рекомендация: Вариант 1 (Упрощение)**

Текущий контейнер работает и заморожен. Для production релиза лучше:
1. Оставить как есть
2. Добавить больше документации
3. Рассмотреть миграцию после стабилизации проекта
