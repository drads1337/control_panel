# Custom Crypto Protocol Migration Plan

## Текущее состояние

### Используемые протоколы
1. **AES-256-GCM** для шифрования payload'ов (через `MasterKeyManager` и `ProjectCrypto`)
2. **Challenge-Response** протокол с SHA-256, HMAC, PBKDF2
3. **Проект-специфичные ключи** для multi-tenant архитектуры
4. **Custom blob format** для передачи зашифрованных данных

### Проблемы текущей реализации
- Самописный протокол вместо стандартных решений
- Сложность поддержки и аудита безопасности
- Зависимость от custom формата данных
- Требует синхронизации изменений между клиентом (C++) и сервером (Python)

## Рекомендация из технического аудита

> Заменить самописный протокол шифрования payload'а в /connect на стандартный TLS (который уже есть) + JWE (JSON Web Encryption), если нужно шифрование на прикладном уровне.

## План миграции

### Фаза 1: Подготовка (Low Risk)
1. ✅ **Анализ текущей реализации** - выполнено
2. **Добавить поддержку JWE** параллельно с существующим протоколом
3. **Создать адаптер** для постепенной миграции
4. **Документировать** оба протокола

### Фаза 2: Постепенная миграция (Medium Risk)
1. **Добавить JWE endpoint** (например, `/api/connect/v2`)
2. **Обновить клиентский код** для поддержки JWE
3. **Тестирование** нового протокола
4. **Мониторинг** использования обоих протоколов

### Фаза 3: Полная миграция (High Risk)
1. **Переключить по умолчанию** на JWE
2. **Deprecate** старый протокол
3. **Удалить** legacy код после полной миграции клиентов

## Технические детали

### JWE (JSON Web Encryption)

**Преимущества:**
- ✅ Стандартный протокол (RFC 7516)
- ✅ Поддержка множества алгоритмов (AES-GCM, RSA-OAEP, etc.)
- ✅ Встроенная поддержка в библиотеках (python-jose, jwcrypto)
- ✅ Легче аудировать безопасность
- ✅ Лучшая совместимость с другими системами

**Реализация:**
```python
from jwcrypto import jwe, jwk
import json

def encrypt_with_jwe(data: dict, key: bytes) -> str:
    """Encrypt data using JWE standard"""
    # Create JWK from key
    jwk_key = jwk.JWK(kty='oct', k=base64url_encode(key))
    
    # Create JWE
    jwetoken = jwe.JWE(
        json.dumps(data),
        json.dumps({"alg": "dir", "enc": "A256GCM"})
    )
    jwetoken.add_recipient(jwk_key)
    
    return jwetoken.serialize(compact=True)

def decrypt_with_jwe(encrypted: str, key: bytes) -> dict:
    """Decrypt JWE token"""
    jwetoken = jwe.JWE()
    jwetoken.deserialize(encrypted)
    
    jwk_key = jwk.JWK(kty='oct', k=base64url_encode(key))
    jwetoken.decrypt(jwk_key)
    
    return json.loads(jwetoken.payload)
```

### Совместимость с текущей архитектурой

**Multi-tenant поддержка:**
- JWE может использовать project-specific keys
- Заголовок JWE может содержать project_id для маршрутизации
- Или использовать разные алгоритмы для разных проектов

**Challenge-Response:**
- Оставить существующий challenge-response протокол
- JWE используется только для шифрования payload'а
- Challenge-response обеспечивает аутентификацию

## Риски и митигация

### Риски
1. **Breaking changes** для существующих клиентов
   - **Митигация:** Поддержка обоих протоколов во время миграции
   
2. **Производительность** (JWE может быть медленнее)
   - **Митигация:** Бенчмарки и оптимизация
   
3. **Сложность миграции** клиентского кода (C++)
   - **Митигация:** Постепенная миграция, подробная документация

### Преимущества миграции
1. ✅ Стандартизация - легче поддерживать
2. ✅ Безопасность - проверенные стандарты
3. ✅ Совместимость - интеграция с другими системами
4. ✅ Аудит - проще проверять безопасность

## Альтернативный подход

Если полная миграция на JWE слишком сложна, можно:

1. **Улучшить текущую реализацию:**
   - Добавить стандартные заголовки (как в JWE)
   - Использовать стандартные алгоритмы (уже используется AES-256-GCM)
   - Улучшить документацию

2. **Использовать TLS только:**
   - Убрать шифрование на прикладном уровне
   - Полагаться только на TLS (mTLS уже реализован)
   - Упростить код

## Рекомендация

**Для production-ready статуса:**

- mTLS уже обеспечивает защиту на транспортном уровне
- Custom crypto протокол работает, но требует улучшения документации

**Для долгосрочной поддержки:**
