# Исправления по результатам аудита кода

## Выполненные исправления

### 1. Замена MD5 на SHA-256 ✅

**Проблема:** Использование устаревшего алгоритма MD5 для генерации хешей кэш-ключей.

**Исправление:**
- `backend/services/cache/cache_service.py`: Заменены все использования `hashlib.md5()` на `hashlib.sha256()`
  - Метод `_generate_cache_key()`: строка 79
  - Метод `_generate_pattern_set_key()`: строка 100

**Примечание:** Остальные файлы уже используют SHA-256 или SHA-512, что соответствует современным стандартам безопасности.

### 2. Конфигурируемый Content-Security-Policy ✅

**Проблема:** CSP был захардкожен в коде, что затрудняло подключение внешних сервисов (CDN, аналитика) без изменения кода.

**Исправление:**
- `backend/config/security_headers.py`: Добавлена поддержка конфигурации CSP через переменные окружения

**Доступные переменные окружения:**

1. **CSP_POLICY** - Полная политика CSP (если задана, используется вместо построения из директив)
2. **CSP_DEFAULT_SRC** - Директива default-src (по умолчанию: `'self'`)
3. **CSP_SCRIPT_SRC** - Директива script-src (по умолчанию: `'self' 'unsafe-inline' 'unsafe-eval' https:`)
4. **CSP_STYLE_SRC** - Директива style-src (по умолчанию: `'self' 'unsafe-inline' https:`)
5. **CSP_IMG_SRC** - Директива img-src (по умолчанию: `'self' data: https: blob:`)
6. **CSP_FONT_SRC** - Директива font-src (по умолчанию: `'self' data: https:`)
7. **CSP_CONNECT_SRC** - Директива connect-src (по умолчанию: `'self' https: wss: ws:`)
8. **CSP_FRAME_ANCESTORS** - Директива frame-ancestors (по умолчанию: `'none'`)
9. **CSP_BASE_URI** - Директива base-uri (по умолчанию: `'self'`)
10. **CSP_FORM_ACTION** - Директива form-action (по умолчанию: `'self'`)
11. **CSP_UPGRADE_INSECURE_REQUESTS** - Включить upgrade-insecure-requests (по умолчанию: `true`)
12. **CSP_BLOCK_MIXED_CONTENT** - Включить block-all-mixed-content (по умолчанию: `true`)
13. **CSP_OBJECT_SRC** - Директива object-src (по умолчанию: `'none'`)
14. **CSP_MEDIA_SRC** - Директива media-src (по умолчанию: `'self' https:`)
15. **CSP_WORKER_SRC** - Директива worker-src (по умолчанию: `'self' blob:`)
16. **CSP_REQUIRE_TRUSTED_TYPES** - Включить require-trusted-types-for (по умолчанию: `true`)

**Пример использования:**

```bash
# Добавить внешний CDN для скриптов
export CSP_SCRIPT_SRC="'self' 'unsafe-inline' 'unsafe-eval' https: https://cdn.example.com"

# Добавить аналитику
export CSP_CONNECT_SRC="'self' https: wss: ws: https://analytics.example.com"

# Или задать полную политику
export CSP_POLICY="default-src 'self'; script-src 'self' https://cdn.example.com; ..."
```

### 3. Проверка проблемных файлов ✅

**Проверка:** Поиск файлов с суффиксами `_1.py`, `_2.py`, `__init___X.py` не выявил проблемных файлов в основной кодовой базе.

## Выявленные проблемы, требующие дальнейшей работы

### 1. Циклические зависимости и ленивые импорты ⚠️

**Проблема:** Широкое использование `get_service()` из `utils.service_helpers` внутри функций создает "ленивые импорты", которые:
- Усложняют статический анализ
- Могут приводить к Runtime Errors
- Указывают на сильную связность модулей

**Статистика:** Найдено ~360 использований `get_service()` в коде.

**Рекомендации:**
1. Постепенный рефакторинг: замена `get_service()` на явную инъекцию зависимостей через конструкторы
2. Использование `TYPE_CHECKING` для type hints, чтобы избежать циклических импортов
3. Выделение общей логики в отдельные сервисы для разрыва циклических зависимостей

**Пример рефакторинга:**

```python
# Было:
def some_function():
    service = get_service('some_service')
    service.do_something()

# Стало:
class SomeClass:
    def __init__(self, some_service):
        self.some_service = some_service
    
    def some_method(self):
        self.some_service.do_something()
```

### 2. Кастомный DI контейнер

**Проблема:** Использование кастомного `ServiceContainer` вместо стандартных решений (Dependency Injector, Punq).

**Рекомендация:** Рассмотреть миграцию на стандартную библиотеку DI для упрощения поддержки и снижения порога входа для новых разработчиков.
