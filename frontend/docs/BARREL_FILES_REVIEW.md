# Barrel Files Review

## Текущее состояние

Проект использует barrel-файлы (`index.ts`) для группировки экспортов, но большая часть кодовой базы уже использует прямые импорты, что является хорошей практикой.

## Результаты ревизии

### Barrel-файлы найдены:

1. **`src/lib/workers/index.ts`** - Экспортирует Web Worker утилиты
   - Используется редко, модули обычно импортируются напрямую
   - ✅ Не критично для производительности

2. **`src/hooks/index.ts`** - Экспортирует хуки
   - Частично используется, но большинство импортов прямые
   - ✅ Приемлемо

3. **`src/entities/index.ts`** - Экспортирует все entities
   - Используется редко, большинство импортов прямые (`from '@/entities/changelog'`)
   - ✅ Хорошая практика - прямые импорты для стабильных модулей

### Рекомендации

1. **Прямые импорты предпочтительны** для "горячих" модулей, которые часто меняются:
   ```ts
   // ✅ Хорошо
   import { usePermissions } from '@/hooks/use-permissions'
   
   // ⚠️ Менее предпочтительно для часто меняющихся модулей
   import { usePermissions } from '@/hooks'
   ```

2. **Barrel-файлы допустимы** для стабильных модулей и группировки связанных экспортов.

3. **Текущая структура оптимальна** - большинство импортов уже прямые, barrel-файлы используются минимально.

## Влияние на сборку

- **Скорость сборки**: Минимальное влияние, так как большинство импортов прямые
- **HMR**: Не критично, так как структура уже оптимизирована
- **Tree-shaking**: Работает корректно благодаря прямым импортам

## Вывод

Текущая структура импортов уже оптимальна. Нет необходимости в масштабном рефакторинге barrel-файлов. Рекомендуется продолжать использовать прямые импорты для часто меняющихся модулей.
