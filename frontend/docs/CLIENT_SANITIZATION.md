# Client-Side Input Sanitization

## Обзор

Этот документ описывает реализацию клиентской санации пользовательского ввода для защиты от XSS (Cross-Site Scripting) атак.

## Важные замечания о безопасности

⚠️ **КРИТИЧЕСКИ ВАЖНО**: Клиентская санация является **вторым рубежом обороны** (defense-in-depth) и **НИКОГДА** не должна быть единственной мерой защиты.

### Принципы безопасности

1. **Основная защита на бэкенде**: Все валидация и санация данных должны выполняться на сервере
2. **Клиентская санация как дополнительный слой**: Клиентская санация предотвращает отправку явно вредоносного контента, но не может быть полностью доверена
3. **Не полагаться на клиент**: Злоумышленник может обойти клиентскую санацию, поэтому бэкенд должен всегда валидировать и санировать данные

## Реализация

### Утилита санации

Файл: `src/lib/sanitization.ts`

Утилита использует библиотеку **DOMPurify** для удаления всех HTML-тегов и JavaScript из пользовательского ввода.

#### Основные функции

- `sanitizeString(value: string)`: Санирует строковое значение, удаляя все HTML/JS
- `sanitizeData<T>(obj: T)`: Рекурсивно санирует объекты и массивы
- `sanitizeForApi<T>(data: T)`: Главная функция для санации данных перед отправкой в API

#### Поля, которые санируются

Утилита автоматически санирует следующие поля (и похожие):
- `description`
- `reason`
- `name`
- `message`
- `title`
- `bio`
- `comment`
- `note`
- `content`
- `text`
- `body`
- `summary`
- `details`
- `remarks`
- `feedback`
- `review`
- `username`
- `first_name`
- `last_name`
- `email`

### Интеграция в API клиент

Файл: `src/shared/api/enhanced-client.ts`

Санация автоматически применяется в request interceptor для всех запросов с методами:
- `POST`
- `PUT`
- `PATCH`

#### Особенности реализации

1. **Автоматическая санация**: Все данные автоматически санируются перед отправкой
2. **Пропуск специальных типов**: `FormData`, `File`, `Blob` не санируются на клиенте (обрабатываются бэкендом)
3. **Безопасная обработка ошибок**: Если санация не удалась, запрос не прерывается (бэкенд должен валидировать)

## Примеры использования

### Автоматическая санация (рекомендуется)

Данные автоматически санируются при использовании `enhancedApi`:

```typescript
import { enhancedApi } from '@/shared/api/enhanced-client'

// Данные автоматически санируются перед отправкой
await enhancedApi.post('/api/games', {
  name: '<script>alert("xss")</script>Game Name',
  description: '<img src=x onerror=alert(1)>Description'
})

// На сервер отправляется:
// {
//   name: 'Game Name',
//   description: ''
// }
```

### Ручная санация (если необходимо)

Если нужно санировать данные вручную:

```typescript
import { sanitizeForApi } from '@/lib/sanitization'

const userInput = {
  name: '<script>alert("xss")</script>Test',
  description: '<b>Description</b>'
}

const cleanData = sanitizeForApi(userInput)
// cleanData = { name: 'Test', description: 'Description' }
```

## Тестирование

### Проверка санации

Для проверки работы санации можно использовать следующие тестовые векторы:

```typescript
const testVectors = [
  '<script>alert("xss")</script>',
  '<img src=x onerror=alert(1)>',
  '<svg onload=alert(1)>',
  'javascript:alert(1)',
  '<iframe src="javascript:alert(1)"></iframe>',
  '<body onload=alert(1)>',
  '<input onfocus=alert(1) autofocus>',
]
```

Все эти векторы должны быть удалены или нейтрализованы санацией.

## Рекомендации для разработчиков

1. **Всегда используйте `enhancedApi`**: Не используйте прямой `axios` или `fetch` для API запросов
2. **Не отключайте санацию**: Даже если данные "доверенные", санация должна оставаться включенной
3. **Проверяйте на бэкенде**: Всегда валидируйте и санируйте данные на сервере
4. **Логируйте подозрительные данные**: Рассмотрите возможность логирования попыток XSS

## Ограничения

1. **Только строковые данные**: Санация работает только со строковыми значениями
2. **Не защищает от всех атак**: Клиентская санация не защищает от:
   - SQL Injection (защита на бэкенде)
   - CSRF (используется отдельная защита)
   - Server-Side XSS (защита на бэкенде)
3. **Производительность**: Рекурсивная санация больших объектов может быть медленной (но обычно незаметно)

## Обновления и поддержка

При добавлении новых полей с пользовательским вводом:
1. Добавьте имя поля в `SANITIZABLE_FIELDS` в `sanitization.ts` (опционально, все строки санируются)
2. Убедитесь, что бэкенд также валидирует и санирует эти поля
